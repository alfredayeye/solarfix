## How the current version was built (keep these decisions unless you have a good reason)

- **Plain static HTML and CSS. No framework, no build step.** Four pages: `index.html`, `investment.html`, `school-of-human-flight.html`, `community.html`. One stylesheet, `assets/css/site.css`, with colours and fonts as variables at the top. One tiny script, `assets/js/site.js`, for the mobile menu only.
- **Design.** Navy (#0f2340) and orange (#e8651a), taken from the facility rendering's logo. Barlow Condensed for headings and Barlow for body text, loaded from Google Fonts. Orange is reserved for actions and key figures. Layout is full-width bands with a 1120px centred column. It is responsive down to 400px with no horizontal scroll, has a skip link and visible focus states, and respects reduced motion. It is light theme only.
- **Images.** Six supplied photos were resized and compressed to JPEG in `assets/img/`: Cape Town aerial (hero), facility concept rendering, child's first flight, para flyer at a tunnel door (cropped), eight-way formation, and Springbok blazers. The originals were large (up to 3624px, 2.4 MB), so keep the optimised set. Every image has descriptive alt text.
- **SEO.** Each page has a unique title and meta description, a canonical URL, Open Graph and Twitter cards, and JSON-LD: Organization and WebSite and a FAQPage (eight questions) on the home page, and WebPage on the others. Also `sitemap.xml`, `robots.txt` and `favicon.svg`.
- **LLM visibility.** `llms.txt` is a plain-text summary of the project and every page. `robots.txt` explicitly allows GPTBot, ClaudeBot, PerplexityBot and Google-Extended. Page copy is written as short, factual, self-contained statements and the FAQ answers stand alone, so they can be quoted accurately.
- **Content rule.** Only summary-level facts are public. The full proposal documents, use-of-funds and financial model are "shared under NDA", per the source documents. Do not add any figure that is not in the source proposals. Do not invent contact details, team members, testimonials or revenue projections.
- The pages were generated by a one-off Python script and only the HTML output was kept. Edit the HTML directly.

## What to do

1. **Review.** Read the repo, run it locally (`python3 -m http.server`), and check all four pages at desktop and phone width. Fix anything broken.
2. **Prepare for Cloudflare Workers (static assets).**
   - Move the deployable files into a `public/` folder: the four HTML files, `assets/`, `favicon.svg`, `robots.txt`, `sitemap.xml`, `llms.txt`. Keep `README.md` and `docs/` at the repo root so they are not served.
   - Add `wrangler.jsonc` with a worker name such as `capetown-wind-factory`, a current `compatibility_date`, and `assets.directory` set to `./public`. No Worker script is needed for a pure static site. Check the current Cloudflare docs for the exact static-assets config and do not guess.
   - Decide URL style. Workers assets serve `/investment` for `investment.html` by default, and the current canonical URLs, sitemap and internal links all use `.html`. Pick one style and make canonicals, sitemap, `llms.txt` and links consistent. Clean URLs without `.html` are preferred.
   - Add a `_headers` file in `public/` with sensible security headers (X-Content-Type-Options, Referrer-Policy, a Content-Security-Policy that allows Google Fonts) and long cache lifetimes for `/assets/*`. Make sure the `.js` file and the fonts still load.
   - Delete `.github/workflows/pages.yml` and `.nojekyll`. They were for GitHub Pages and are not needed.
3. **Deploy.** Run `wrangler deploy` to a `*.workers.dev` URL first. Verify every page, every image, the sitemap and `llms.txt` over HTTPS. Do not attach a custom domain until I confirm which one.
4. **Custom domains.**
   - **Owned: `schoolofhumanflight.com`.** I have registered it. Use it for the School of Human Flight programme. Default plan: add it to the Cloudflare account as a zone and make it a Workers custom domain that serves the SOHF page as its own home (`/`). Do not serve the same page on two domains with different canonicals, because that is duplicate content. Either give the SOHF domain its own canonical, JSON-LD and sitemap, or 301 it to the SOHF page on the main domain. Ask me which before building it. Add `www` handling either way.
   - **Not yet bought: `capetownwindfactory.com`.** It was available on 14 Oct 2026 and was the recommended primary. Do not assume it is still free. Ask me before replacing any URLs, and if the final domain differs, update canonicals, Open Graph URLs, JSON-LD, sitemap, robots.txt and `llms.txt`.
   - Until I confirm the main domain, deploy only to `*.workers.dev`.
5. **Contact form.** The contact section currently shows a placeholder address, `invest@capetownwindfactory.com`, which is not a real mailbox. Ask me for the real address. If I want a form instead, build it as a small Worker endpoint with Turnstile for spam protection, and have it email me. Do not store submissions in the repo.
6. **Verify.** Run Lighthouse (mobile) and aim for 95+ on Performance, Accessibility, Best Practices and SEO. Check the JSON-LD with a schema validator. Confirm social cards render with the share image.
